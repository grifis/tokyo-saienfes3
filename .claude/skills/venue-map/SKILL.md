# 会場マップとルート表示

## 目的
来場者が「次の公演の部屋・建物まで、どう行くか」を、当日スマホで迷わず分かるようにする。
**判定はしない**：重なりの警告・スキマ提案は主催の設定（0 分移動 OK／前後 5 分）のまま。地図が出すのは「どこをどう通るか」と、建物の外を歩くときの目安の時間だけ。

仕様の正本：`docs/OUTDOOR_ROUTE.md`。ここはそれを、ほかの会場で作り直すための手順と勘所にまとめたもの。

## 全体の構成

| 役割 | ファイル |
|---|---|
| ルート計算（ダイクストラ法・階の区間分け・徒歩の時間） | `src/core/VenueRouter.js` |
| 全画面のルート案内（線・札・カメラ・階の切り替え・ズーム） | `src/ui/RouteView.js` |
| 予定一覧の移動の帯・「ルート表示」ボタン・使い方の案内 | `src/ui/MyScheduleDialog.js`・`src/ui/CoachMarks.js` |
| フェスの当日の判定 | `src/core/EventDays.js` |
| 読み込み（設定シートの「会場マップURL」） | `src/main.js` の `loadVenueMap` |
| 周辺地図の生成（OSM → SVG＋歩く道の網） | `tools/outdoor-map/osm_outdoor.py`（README あり） |
| 会場ごとの生成スクリプトの手本 | `tools/sample-venue/build_sample_hall*.py` |
| 代行者用の編集ツール（点・線・出入口・link・note） | `tools/venue-editor.html` |
| 検査 | `tests/venue-router.test.js` |

会場マップが無い（URL が空・読み込み失敗）ときは、地図の機能は何も出ない。既存の会場を壊さないため、足す設定はすべて省略できる形にする。

## venue_map.json の形

```jsonc
{
  "name": "○○会場（簡略図）",
  "attribution": "屋外の地図データ © OpenStreetMap contributors（ODbL 1.0）",
  "floors": [
    { "id": "2F", "label": "2階", "level": 2, "image": "./2f.svg", "width": 1720, "height": 1060,
      "metersPerPx": 0.03,
      "footprint": { "floor": "OUT", "outline": [x0, y0, x1, y1], "center": [cx, cy], "size": [長辺px, 短辺px], "rotation": 度 } },
    { "id": "OUT", "label": "屋外", "outdoor": true, "image": "./outdoor.svg", "width": 1720, "height": 1240,
      "metersPerPx": 0.09, "focus": [x0, y0, x1, y1], "geo": { … } }
  ],
  "nodes": [
    { "id": "2f-c1", "floor": "2F", "x": 340, "y": 480 },                                   // 通路の点
    { "id": "2f-r1", "floor": "2F", "x": 345, "y": 240, "room": "研修室A", "aliases": ["研修室Ａ"] }, // 部屋（入口のすぐ内側）
    { "id": "2f-ev", "floor": "2F", "x": 1375, "y": 430, "kind": "elevator", "name": "エレベーター" },
    { "id": "1f-ent", "floor": "1F", "x": 990, "y": 905, "kind": "entrance", "name": "正面入口", "link": "main-entrance" },
    { "id": "out-ent", "floor": "OUT", "x": 912, "y": 600, "kind": "entrance", "name": "本館 正面入口", "link": "main-entrance" },
    { "id": "out-b", "floor": "OUT", "x": 400, "y": 380, "room": "別館B", "note": "通り沿い・角の近く" }
  ],
  "edges": [["2f-c1", "2f-r1"], { "a": "2f-ev", "b": "1f-ev", "weight": 10 }]
}
```

- **部屋名**：公演データの「会場(部屋)」と結び付く。全角半角・空白の違いは吸収する（`normalizeRoomName`）。表記の違う呼び名は `aliases`
- **kind**：`stairs`・`elevator`・`entrance`（建物の出入口。ドアの印で案内する）。通路の点は省略
- **link**：同じ値の点を、`floors` の並びで隣り合う階どうしでつなぐ（edges に書いた接続があれば二重にしない）。表示名 `name` は階ごとに変えてよい（「正面入口」と「本館 正面入口」）
- **重み**：同じ階は 2 点間の距離。**すべての階に `metersPerPx` があればメートル**、1 つでも無ければ px（互換）。階をまたぐ既定はメートルなら 階段 15・エレベーター 30・出入口 5、px なら 400。edges の `weight` が優先
- **level**：階の上下（切り替えの向き）。無ければ ID・表示名の数字（B1 は -1）
- **outdoor**：建物の外の周辺地図を 1 枚の「階」として扱う。`focus` は「全体」表示で見せる範囲
- **footprint**：屋内図の外形の四角（`outline`）を、周辺地図の上で `center` を中心に `size` の大きさで `rotation` 度回して置く。屋内 ⇔ 屋外のズームに使う
- **note**：到着した部屋・建物の目印。到着の案内に出る
- 1 階の図が無い建物：上の階のエレベーターと屋外の「1階 出入口」を edges で直接つなぎ、weight に「降りて出入口まで」のメートルを書く。案内は「エレベーターで降り、1階 出入口から外へ」（`through`）

## 作る手順

### 1. 屋内の各階の図（SVG）を起こす
1. **会場の公式の見取り図を集める**。階ごとに、ほかのページ（研修室・ホールの個別ページなど）に詳しい図があることが多いので探す。無い階は主催・あなたに確かめる（推測で描かない）
2. **向きを確かめる**。公式の図どうしで向きが違うことがある（ある階だけ 180° 回っている等）。エレベーター・階段・トイレなど、各階で同じ位置にあるはずの設備で突き合わせる
3. 生成スクリプトに部屋を多角形で書き、SVG を出す（`build_sample_hall2.py` の `FLOORS`・`svg_floor` が手本）。手で SVG を描かない（作り直せなくなる）
   - 部屋の種類：`room`（公演に使う・白）・`service`（倉庫・給湯室など・薄灰）・`closed`（**入れない部屋**：濃い灰色＋「立入不可」）・`ev`
   - 建物の外形（`OUTLINE`）で部屋を切り取る。外形の四角が footprint の `outline` になる
   - 右下に灰色の小さな文字で、必要なら「この地図はサンプルです」。枠や黄色で目立たせない（視線を取られる）
4. 縮尺 `metersPerPx` を決める（実際の建物の長さ ÷ 図の px。屋外があるなら footprint から求める）

### 2. 通路の網を引く
- 部屋の点は**入口のすぐ内側**に置く。廊下の点を連ね、部屋の点は入口に近い廊下の点からだけつなぐ
- **入れない部屋**：`closed` で描き、点も線も置かない（ルートが通らない）
- **ある部屋を経由しないと入れない部屋**：廊下からその部屋へ直接の線を引かず、経由する部屋の中の点からだけつなぐ。電子的な壁のような仕組みは要らない。**線を引かないこと＝通れないこと**
- **細い通路**：図形のほうで隙間を作る（隣の設備を少し小さくする）。その隙間の中に点を 2 つ以上連ねて通す。図に隙間が見えないと、来場者は「壁を抜けている」と感じる
- 階段・エレベーターは各階で同じ位置。階どうしは `link` か edges でつなぐ

### 3. 建物の外（周辺地図）を作る：`osm_outdoor.py`
```python
m = OutdoorMap.load(cache_path, center=(lat, lon), radius_m=…, keep_names=False)  # 保存があれば通信しない
m.set_view(building_ways, margin_m=…)        # 描く範囲と縮尺。歩ける道の網を作る
door = m.door_of(way_ids)                     # 外壁のうち、いちばん道に近い点（出入口の目安）
m.add_point('out-x', door, kind='entrance', name='…', link='…')  # 近い道につなぐ
m.set_focus(way_ids, margin_m=…)              # 「全体」表示の範囲
svg = m.svg(highlights, badge='…', street_labels=False)
floor, nodes, edges = m.venue_floor('OUT', '屋外', './outdoor.svg')
```
- 取得は Overpass API → だめなら OSM API。結果をファイルに保存し、作り直しは通信なしでできるようにする
- 歩ける道から、高速道路・自転車専用・私道、地下街・地下道・建物の中の通路（tunnel・負の layer・indoor・corridor）を除く。地上の地図に重ねると分かりにくいため
- **出入口の位置**：推定がずれていたら、編集ツールで点を正しい位置へ動かし、出てくる緯度経度を設定ファイル（例：`doors.json`）に書く。px ではなく緯度経度で持つので、作り直しても残る
- **footprint**：建物の OSM の形の最小外接長方形（`footprint_box`）に、屋内図の外形の四角を合わせる。**どちらの辺が正面入口か**は主催・会場に確かめてから決める（屋内図の下をその向きに合わせる）
- 生成結果は、同じデータからは毎回同じファイルになるようにする（点と線を並べてから書き出す）

### 4. 確かめる
```bash
node --test tests/venue-router.test.js   # ルート計算の検査（ファイルを名指しする）
npm run build
```
- 公演の部屋名がすべて地図にあること：`router.unknownRooms(shows.map(s => s.room))` が空（読み込み時にコンソールにも出る）
- 実機で：その日の予定を 2 つ以上選ぶ → 予定一覧の「ルート表示」→ 移動の帯 →「ルートを見る」。屋内 → 出入口 →（ズームアウト）→ 周辺地図 → 到着、逆向きはズームイン
- スクリーンショットは、全体表示と拡大表示の両方で撮る。入れない部屋を通っていないか、経由の部屋を必ず通るか、細い通路が図の隙間を通っているかを目で確かめる

## ルート表示の決まり（画面）

- **予定一覧**：移動の帯は、考えている間は出さない。「ルート表示」（スキマ探索の横・半分ずつの幅）を押したときだけ出す
  - **フェスの当日に、その日の予定を開いたときは最初から出す**（`eventDayToday`：日のラベルの月日、無ければ開催日から続く日で判定）
  - 会場マップが無ければボタンを隠す。2 公演以上選ぶまで押せない
  - はじめて予定一覧を開いたとき、2 つのボタンを使い方の案内（コーチマーク）で 1 つずつ紹介する。「次へ／わかった」は、そのダイアログの主ボタンと同じ色
- **移動の帯**：「（階）部屋 から（階）部屋 へ（○○から外へ）徒歩約 N 分」と「ルートを見る」。周辺地図の上の部屋には階の名前を付けない
- **徒歩の時間**：**建物の外を通るときだけ**出す。分速 80m、切り上げ、最短 1 分。重なりの警告には使わない
- **全画面の案内**
  - 最初は全体、ボタンで「拡大 ⇔ 全体」。ボタンには押すと次にどうなるかを書く
  - 線は約 0.5 秒で伸びる。色は地図アプリの青（#1a73e8／縁 #185abc）
  - 屋内 ⇔ 屋内：上下のスライド＋フェード（0.38 秒・ズームなし）。上の階へは上から、下の階へは下から入る
  - 屋内 ⇔ 屋外：ズームアウト／ズームイン（約 1.1 秒）。屋内図が建物の形へ縮みながら回る。ズームが終わってから線を描く
    - カメラの補間は**建物（footprint の中心）の画面上の位置**をなめらかに動かす（画面の中央を基準にすると、建物が全体表示の端にあるとき、途中で画面から消える）
  - 動きを減らす設定（prefers-reduced-motion）では即座に切り替える
  - 出入口はドアの印。「正面入口から外へ」「別館 入口から1階へ」。到着の案内に `note`
  - 階段で終わる区間でも、次の階へは自動で進まない。利用者が「○階へ」を押したときに切り替える

## 守ること

1. **サンプルに実在の施設名・通りの名前・お店の名前を出さない**。画面にも、リポジトリのファイル（パス・ID・コメント・OSM の保存データ）にも。部屋・建物は一般名（研修室A・別館B など）。OSM は `keep_names=False`・`street_labels=False`。コミット前に名前で検索して確かめる
2. **OSM の出典**：地図に「地図データ © OpenStreetMap contributors」を必ず入れる。取得したデータと、そこから作った座標を公開するときは ODbL 1.0（`LICENSE-OSM.md` を同じフォルダに置く）
3. **主催の判定を覆さない**：ルートの長さで重なりを判定しない
4. 日本の OSM は歩道・横断歩道が描かれていない所が多い。生成した道の網は編集ツールで開き、大通りの横断などを人が確かめて直す

## 過去の失敗（同じことをしない）

| 失敗 | どう直したか・次からの確かめ方 |
|---|---|
| ある階の図だけ向きが逆だった | 公式の図どうしを、各階で同じ位置の設備で突き合わせてから起こす |
| 一部の階の公式図を見落とし、推測で描いた | 階ごとの個別ページまで探す。無ければ聞く |
| 「小さめにして」を幅と取り違えた（本当は高さ） | 大きさの指示は「幅・高さのどちら」を確かめる。同じ高さにそろえるべき部屋どうしも確かめる |
| 細い通路を図に描かずに線だけ通した | 図形を縮めて隙間を作り、その中に点を通す |
| ズームの途中で建物が画面の外へ消えた | 補間の基準を画面の中央から、建物の位置（anchor）に変えた |
| 生成のたびにファイルの中身が変わった | 点と線を並べてから書き出す（差分が出ない） |
| 推定の出入口がずれた | 緯度経度の上書き（doors.json）で直す。px で直さない |
| サンプルに施設名・通りの名前が残った（地図の外のファイルにも） | 画面に出ない保存データ・パス名も含めて検索して消す |
| 生成スクリプトのキャッシュ（`__pycache__`）をコミットした | `.gitignore` に入れる |
